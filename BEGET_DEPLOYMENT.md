# Боевой сайт alymprofi.ru

На Beget работает исходный сайт с самописной PHP-админкой `/admin/`.
Сохранение в админке сразу меняет публичные файлы; отдельная публикация для
заказчика не требуется. Каталог для поиска хранится в
`site/admin/storage/catalog.json`, первоначальный индекс — в `admin/data/`.

При обновлении кода передавайте только изменённые PHP, JS и CSS-файлы.
Не заменяйте весь каталог сайта локальной копией: это перезапишет сохранённые
заказчиком тексты, изображения и карточки. Не заменяйте `admin/storage/`,
`admin/config.local.php` и `upload/admin/`.

Для исправления существующего контента читайте текущие файлы на хостинге,
меняйте только нужные поля и создавайте резервные копии. Админка использует
общую блокировку записи каталога, а редактор товара проверяет версию формы.
Устаревшая вкладка должна быть открыта заново до повторного сохранения.

Проверки редактора:

```sh
python3 tools/test_admin_editor.py
php tools/audit_admin_templates.php
```

Первая команда проверяет сохранение через HTTP в изолированной временной
копии с тестовыми фото и отзывами. Вторая проверяет все шаблоны в памяти и
не меняет файлы. Боевой HTTP-сайт использует PHP 8.2; для соответствующих
проверок на Beget используйте `/usr/local/bin/php8.2`. Стандартная команда
`php` может указывать на старую версию.

`tools/remove_imported_review.php` удаляет только указанный заказчиком старый
отзыв Сергея про остекление, сохраняя остальные поля. Скрипт читает актуальные
карточки, делает резервные копии и допускает повторный запуск.

Индексация боевого сайта открыта по просьбе заказчика 07.10.2026.
Публичные страницы не получают `X-Robots-Tag: noindex`; запрет остаётся
в админке. `robots.txt` разрешает обход сайта и закрывает служебные адреса.
`/sitemap.xml` выдаётся через `sitemap.php`: текущие товары и категории
берутся из рабочего каталога, остальные публичные страницы — из архивных
карт с проверкой существования. Все ссылки используют `https://alymprofi.ru`.
Карта обновляется при добавлении и удалении товаров через админку.

Файлы оформления из `bitrix/cache/css` и `bitrix/cache/js` имеют постоянные
копии в `assets/design/css` и `assets/design/js`. Правило `.htaccess` обслуживает
старые адреса из этой папки, даже если файлы в `bitrix/cache` удалены.
Не удаляйте `assets/design` при очистке кеша: это CSS и JavaScript сайта.
При выгрузке изменённого файла из `bitrix/cache/css` или `bitrix/cache/js`
инструмент `deploy_beget_code.py` также обновляет его постоянную копию.

После инцидента 06.10.2026 полная выгрузка локальных HTML запрещена также
в `AGENTS.md` и в инструменте выгрузки. Используйте:

```sh
python3 tools/deploy_beget_code.py --apply admin/bootstrap.php admin/editor.php
```

Без `--apply` команда только показывает план. Она отклоняет HTML, карточки,
архивы пагинации, загрузки, настройки и данные заказчика.

Все поля товара сохраняются в закрытом `admin/storage/product-content/`,
каждая полная версия — в `product-history/`. `content.php` и диспетчер
пагинации накладывают сохранённые данные на исходные шаблоны при выдаче
страниц, включая каталог, популярные товары и связанные товары. Даже
случайная замена старого шаблона не сбрасывает сохранённые поля в админке
или на сайте. GET-запросы не изменяют файлы и не создают административные
сессии. Начальные данные импортируются перед включением этого обработчика.

Сохранённые названия и изображения категорий применяются также к карточкам
категорий на главной странице. Если изображение ещё не задано в рабочем
каталоге, сохраняется исходная фотография шаблона.
