# Публикация проекта

- Исходники: https://github.com/Kibosh13/forma-201/tree/main
- Демонстрация: https://kibosh13.github.io/forma-201/
- Публикуемая ветка: `gh-pages`, корень `/`, без Jekyll.

Проект — статический снимок публичного сайта. `serve.py` нужен только для удобного локального просмотра исходных адресов; PHP-движок, база данных и админка Битрикса отсутствуют. Для GitHub Pages используется отдельный экспорт, не требующий сервера.

## Ветки и файлы

`main` содержит `site/` с HTML, фотографиями, стилями и скриптами по исходным путям, минимальные карты файлов в `metadata/`, локальный сервер и инструменты экспорта. Публичные CSS/JS внутри `site/bitrix/cache/` необходимы для оформления сайта и сохранены. Это не локальные кэши сборки.

`gh-pages` содержит только готовую демонстрацию. `.prod` и `.tag` экспортируются в каталоги с `index.html`, а сохранённые варианты пагинации — в `_pages/`. Внутренние ссылки преобразуются автоматически с учётом `/forma-201/`. Изображения сохраняют исходные имена и структуру каталогов.

`original-text/`, журналы скачивания, подробные локальные отчёты, `.pages-build/`, `.env*`, базы данных и локальные зависимости в Git не включаются. Архивы проекта не создаются и не коммитятся.

## Запуск

Требуется Python 3.9+; сторонние библиотеки не нужны.

```sh
python3 serve.py
```

Локальная исходная копия: http://127.0.0.1:8847/.

Собрать и проверить Pages-версию:

```sh
python3 tools/export_pages.py
python3 tools/check_pages.py
```

## Обновление

Сначала измените нужные файлы в `site/`, сохраните изменения в `main` и отправьте их:

```sh
git switch main
git pull --ff-only origin main
git add <изменённые-файлы>
git commit -m "Describe the change"
git push origin main
```

Затем опубликуйте обновлённую демонстрацию:

```sh
git fetch origin gh-pages
python3 tools/publish_demo.py --push
```

Скрипт собирает и проверяет демонстрацию, создаёт очередной коммит `gh-pages` с сохранением истории и выполняет обычный `git push` без `--force`. Он не переключает рабочую ветку `main` и не затрагивает её индекс. Если результат не изменился, новый коммит демонстрации не создаётся. Файлы и Git-объекты передаются по изменениям, без перезаписи большого архива. Если удалённая ветка изменилась независимо, обычный push будет отклонён: сначала нужно согласовать изменения.

Требуется существующая авторизация `gh auth login`; секреты в проект не записываются. Первый локальный запуск публикации в новом клоне использует удалённую `gh-pages` как предка.

Если добавляются новые страницы или ресурсы, дополните `metadata/manifest.json`: экспорт использует карту сохранённых файлов. При замене существующего фото путь менять не нужно; миниатюры в `resize_cache` остаются отдельными файлами.

## Демонстрация

Доступны страницы, каталог, все 698 сохранённых карточек товаров, фотографии, галереи, навигация, сохранённая пагинация, PDF и два локальных видеоролика.

Отключены:

- отправка заявок, обратного звонка и отзывов;
- обработка корзины, оформление и оплата заказов;
- серверный поиск, подсказки и произвольные фильтры;
- админка, авторизация и любые функции базы данных;
- аналитика, онлайн-чат, внешние карты и встроенные сторонние видео.

Все страницы явно помечены как демонстрация. Формы и кнопки отправки/корзины перехватываются до обработчиков исходного сайта. Content Security Policy запрещает сетевые API-запросы, внешние фреймы и отправку форм. Старый баннер согласия на аналитику в демонстрации скрыт, поскольку аналитика отключена. Недоступные уже на источнике зависимости CSS исключаются из экспортированных стилей; отсутствующее видео не подменяется новым содержимым.

## Индексация

В **каждом HTML-файле**, включая карточки, пагинацию, служебную страницу и `404.html`, задано:

```html
<meta name="robots" content="noindex, nofollow, noarchive, nosnippet, noimageindex">
```

Исходные XML-карты сайта не публикуются в демоверсии. `tools/check_pages.py` проверяет наличие `noindex` во всех страницах и существование локальных ссылок/ресурсов.

HTML намеренно не закрывается от обхода: поисковый робот должен прочитать `noindex`. `robots.txt` в каталоге проекта не управляет всем доменом `kibosh13.github.io`; запрет индексации страниц основан на метатегах. В корневом `robots.txt` репозитория `Kibosh13/Kibosh13.github.io`, ветка `gh-pages`, сохранён общий `Disallow: /` и добавлены исключения только для HTML этой демонстрации:

```text
Allow: /forma-201/$
Allow: /forma-201/*/$
Allow: /forma-201/*.html$
```

Так поисковики могут прочитать `noindex` у страниц, а изображения, PDF и другие вложения сохраняют исходный запрет обхода. При будущей перепубликации корневого сайта нужно сохранить эти три правила. Остальные проекты не затронуты. GitHub Pages не предоставляет в этом проекте произвольные HTTP-заголовки для PDF и прочих файлов. `noindex` не является паролем или ограничением доступа: репозиторий и демоверсия публичные.

Справка: [Google — noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).
